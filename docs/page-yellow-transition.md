# ページ遷移の黄色カバー

管理画面headに登録済みの `hexPageTransition`（ページ間View Transition）と組み合わせて動作する。

- 対象は既存の遷移対象リンクと同じ。同一ページのアンカー、外部リンク、別タブ、ダウンロード、修飾キー付きクリックは通常動作。
- head側が遷移先をsessionStorageへ保存した後、hex.js側でクリック位置の丸を650msかけて拡大する。
- ヘッダー高さを除いた領域だけを `#f7d04f` で覆う。黄色カーソルとClick表示は開始時に隠す。
- 黄色で覆われた旧ページのスナップショットから、head側の既存の丸開き（1100ms）で遷移先を表示する。
- hex.js先頭でhead連携の `anchorReady` を拡張し、アンカー準備に加えて画面準備用の幕がDOMから外れるまで丸開きを開始しない。幕がフェード中の280msも含む。引き継ぎ中の準備幕は黄色に統一する。
- PC/SPのCMSヘッダーメニューも内部ページへの移動だけ一時リンクを介して同じ演出へ接続。子メニュー開閉、外部・別タブ、同一ページのアンカーは従来動作。
- ヘッダー経由は `hex-header-intro-v1` で導入文表示の指定を渡す。導入文がある遷移先では、ヘッダー経由のページ間丸開きを抑止し、黄色背景の導入文を表示可能になった時点から従来の2秒間表示し、その後ページヒーローの丸開きを行う。導入文がないページは通常のページ間表示へ戻る。
- 戻る操作のBFCache復元時はカバーを解除し、停止したLenisを復元する。
- View Transitionが未対応、既存head連携がない、または動きを減らす設定の場合は通常のリンク動作を維持する。

検証：既存headスクリプトと実際のhex.js処理を用いたローカル2ページで、クリック直後のカーソル非表示、ヘッダー下80pxからの黄色カバー、遷移先到着、履歴で戻った際のカバー解除を確認。
